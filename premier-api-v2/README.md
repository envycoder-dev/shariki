# Premier

Тёмный чат с ИИ-моделями: чаты, проекты, выбор модели, ответы в реальном времени.

## Запуск
**На сервере** — см. [DEPLOY.md](DEPLOY.md): установка одной командой с HTTPS, отдельным пользователем, фаерволом и бэкапами.

Нужен Node.js 22.13+ (в нём встроенная база SQLite — ставить ничего не нужно).

```
node server.js
```
Откройте http://localhost:3000 — главная страница, чат — http://localhost:3000/chat

## Хранение данных
Все данные — в одном файле SQLite `data/premier.db` (встроенный модуль Node.js, без внешних библиотек): пользователи, сессии, платежи — отдельные таблицы с индексами; чаты — таблица «один чат — одна строка» с номером версии; настройки, память, расход по дням — записи «ключ → JSON».
- Запись атомарная (транзакции, журнал WAL): падение сервера посреди записи не портит данные; подтверждение оплаты, начисление дней и промокод применяются вместе.
- Быстрее при росте: на 10 000 пользователей проверка входа — ~2000 запросов/с против ~65 с JSON-файлами.
- История платежей больше не обрезается (раньше хранились последние 5000).
- **Переход со старой версии автоматический**: при первом запуске JSON-файлы из `data/` переносятся в базу, а сами файлы откладываются в `data/legacy-json-<дата>/` (можно удалить, когда убедитесь, что всё на месте).
- Картинки, файлы и опубликованные сайты по-прежнему лежат файлами в `data/`.
- Снимок базы без остановки: `node deploy/db-snapshot.js data/premier.db копия.db`.

## Тесты
```
npm test
```
Проверки на встроенном `node --test`, без зависимостей и без интернета: база и перенос старых данных, синхронизация чатов и конфликты, вход и доступ к панели, вход через GitHub (на поддельном GitHub), выход за папку `public`, фильтр внутренних адресов, песочница Python, подтверждения помощника, ограничение перебора кодов, сетевой прокси Chromium (DNS rebinding, HTTP/CONNECT, редиректы, авторизация и заголовки). Серверные тесты работают с копией приложения во временной папке — ваши данные не трогаются. Запускайте перед каждым обновлением сервера.

## API для Cursor, Codex, Claude Code
Пользователи подключают модели Premier к редакторам и агентам. Кабинет — **/developers** (вкладка «API» в настройках аккаунта ведёт туда же).
- **Протоколы:** OpenAI Chat Completions (`/v1/chat/completions` — Cursor, Cline, Roo, Kilo, OpenCode, Aider, SDK), OpenAI Responses (`/v1/responses` — Codex), Anthropic Messages (`/v1/messages`, `/v1/messages/count_tokens` — Claude Code), список моделей `/v1/models`. Провайдеры моделей — те же OpenAI-совместимые, что и для чата: шлюз сам переводит запросы, инструменты, потоки, размышления и ошибки.
- **Подключение одной командой:** `curl -fsSL https://ваш-домен/connect.sh | sh` (Windows: `irm https://ваш-домен/connect.ps1 | iex`). Скрипт показывает код, пользователь подтверждает его в кабинете, ключ сам прописывается в Claude Code (`~/.claude/settings.json`) и/или Codex (`~/.codex/config.toml`); старые файлы сохраняются рядом как `*.bak-дата`.
- **Списание:** каждый запрос к модели стоит столько же сообщений, сколько её «стоимость запроса» в чате, из общего дневного лимита. Если модель ничего не ответила (ошибка, обрыв до первого слова) — сообщение возвращается. Доступ к моделям — по тем же тарифам, что и в чате.
- **Ключи:** вида `prm_…`, в базе хранится только хэш. До 10 ключей на аккаунт; у ключа можно ограничить модели и IP-адреса, задать срок, перевыпустить.
- **Лимиты:** 60 запросов в минуту и 6 одновременных на аккаунт (`API_RPM`, `API_CONCURRENCY`), тело запроса до 32 МБ (`API_BODY_MB`). Журнал запросов (без текстов) хранится 31 день.
- **Панель → Модели:** у каждой модели постоянный ID для API (назначается по названию) и отметка «готова для агентов» — шлюз сам раз в 3 дня проверяет, умеет ли модель вызывать инструменты (без этого Claude Code и Codex с ней не работают). Если провайдер сам понимает протокол Anthropic или OpenAI Responses, в карточке модели можно включить «Прямой протокол» — запросы пойдут без перевода, с кэшем промпта. Переключатель «API для пользователей» выключает API целиком.

## Мониторинг
- `GET /healthz` — «жив ли сервер» (проверяет и базу): `200 {"ok":true,…}` или `503`. Подходит для UptimeRobot и т. п.
- **/panelp → Обзор → Сервер**: сколько работает, память, ошибки за сутки; ниже — последние ошибки в коде с местом, где они случились.
- **Оповещения в Telegram**: задайте `ALERT_TELEGRAM_TOKEN` и `ALERT_TELEGRAM_CHAT` (или `ALERT_WEBHOOK_URL`) — придут ошибки в коде и падения сервера. Одинаковые — не чаще раза в 10 минут, всего не больше 20 в час.
- На сервере (DEPLOY.md) раз в минуту работает `premier-health.timer`: если сайт не отвечает 2 минуты — перезапуск и сообщение в Telegram, потом — «снова работает».

## Аккаунты
- Чат (`/chat`) доступен только после входа. Страница входа и регистрации — `/login`, через Google или GitHub (настройка — DEPLOY.md, «Вход через Google» и «Вход через GitHub»). Аккаунты с одной и той же подтверждённой почтой объединяются: можно входить любым способом.
- Вход сохраняется на 180 дней — даже после перезапуска сервера. В базе хранится только хэш токена сессии, а не он сам.
- **/panelp → Пользователи**: создать аккаунт, удалить аккаунт (пользователь сразу теряет доступ), включить/выключить открытую регистрацию.
- Чаты хранятся на сервере и в браузере (отдельно для каждого аккаунта) и одинаковые на всех устройствах.

## Синхронизация чатов
- Браузер отправляет на сервер **только изменённые чаты** (`POST /api/sync`), а забирает только то, что поменялось с прошлого раза (`GET /api/sync?since=N`). Раньше при каждом изменении туда-обратно ходили все чаты целиком.
- Правка одного чата на двух устройствах одновременно: сервер не затирает чужую версию, а возвращает её; остаётся более полная (больше сообщений). Правки разных чатов просто объединяются.
- Удаление чата приходит на остальные устройства и важнее правки.
- Открытый чат, выбранный проект и боковая панель у каждого устройства свои; проекты, модель и порядок чатов — общие. Новое устройство берёт проекты с сервера.
- Старый `GET/PUT /api/state` (весь список целиком) работает, так что вкладки, открытые до обновления, не сломаются. Перенос старых чатов в новую таблицу — автоматический при запуске.

## Структура клиента
Код чата — в `public/js/`, обычные скрипты, подключаются в `chat.html` по порядку (общие переменные и синхронизация — в `01-core.js`):
`00-artifact-state` (общие с сервером функции закрепления версии) · `01-core` (состояние, синхронизация, утилиты) · `02-markdown` (разметка, код, сайты-артефакты) · `03-archives` (ZIP/TAR.GZ) · `04-render` · `05-chat` (модели, отправка, поток ответа) · `06-pane` (панель сайта) · `07-attachments` (файлы, PDF/Word/Excel) · `08-projects` (проекты, публикация) · `09-events` · `10-account` (аккаунт, память) · `11-voice` (голос и озвучка) · `12-picker` (выбор элемента на сайте) · `13-billing` (тарифы, оплата) · `14-start` (запуск). После правок поднимите `?v=` у скриптов в `chat.html`, чтобы браузеры не взяли старую версию.

## Панель управления
Откройте `https://ваш-домен/panelp` и введите пароль (переменная `ADMIN_PASSWORD`, от 12 символов; если её нет или пароль простой — Premier при первом запуске создаст случайный, напечатает его в лог и сохранит в `data/admin-password.txt`). В чате кнопки панели нет. Разделы: Обзор, Модели, Тарифы и оплата, Пользователи, Платежи, Промокоды, Инструменты.

## Подключение модели
1. `/panelp` → «Модели» → «Добавить модель». Есть готовые заготовки: **Kimi K3** и Kimi K2.5 через OpenRouter — остаётся вставить ключ OpenRouter.
2. Отметьте, в каких тарифах доступна модель (Free / Pro / Max), и при желании — «Сделать моделью по умолчанию».
3. «Проверить» → «Подключить». Тарифы, «по умолчанию» и стоимость запроса меняются прямо в карточке модели.

Модель по умолчанию выбирается у новых пользователей. Если она не входит в тариф пользователя, ему автоматически включается доступная модель.

Поддерживаются любые OpenAI-совместимые API. Примеры URL:
- OpenAI — `https://api.openai.com/v1`
- OpenRouter — `https://openrouter.ai/api/v1` (Claude, Gemini, Llama и др. по одному ключу)
- DeepSeek — `https://api.deepseek.com/v1`
- Groq — `https://api.groq.com/openai/v1`
- Anthropic — `https://api.anthropic.com/v1/` (OpenAI-совместимый режим)

## Создание сайтов
Попросите, например: «создай простой сайт для кофейни». Модель пришлёт HTML-файл,
а справа откроется окно: пока код пишется — вкладка «Код», когда готов — живое «Превью».
Там же: перезапуск, открыть в новой вкладке, скачать .html, копировать код.
Чтобы поправить сайт, просто напишите, что изменить, — придёт новая версия.
Превью работает в изолированной песочнице и не имеет доступа к Premier.
Инструкцию для модели можно переопределить переменной `SYSTEM_PROMPT`.

### Правки существующей игры/сайта
«Доработай траву», «улучши траву», «измени», «добавь» при наличии текущей версии
включают **режим правки**, а «создай новую игру» / «с нуля» — **режим создания**.
В правке актуальный код закрепляется отдельно от истории и не выпадает при её
обрезке до 40 сообщений. В каждом чате своя версия; новый чат не наследует чужой код.

Модель предлагает JSON с точечными заменами в существующих файлах.
Сервер проверяет точное уникальное совпадение каждого исходного фрагмента,
отсутствие пересечений и ограничение объёма, затем сам собирает полный обновлённый HTML/проект.
Неизменённые участки файлов сохраняются буквально; полный новый HTML от модели
в режиме правки не принимается вместо точечных замен.

Некорректный ответ исправляется максимум одним дополнительным запросом.
Если исправить не удалось, исходная версия остаётся закреплённой.
Успешная правка обновляет превью; прошлые карточки остаются в истории.
Чтобы взять старую версию за основу, откройте её карточку и напишите правку.
Счётчик создания новых сайтов при правке не расходуется; лимит сообщений действует.

Ограничения: до 20 независимых замен, не более половины старого кода и не более
половины размера файла в новых блоках на один запрос. Большую переработку
разбейте на шаги или явно запросите создание заново. Максимальный закрепляемый исходник —
2 МиБ символов, без тихого обрезания.

Превью перезапускается при обновлении: положение игрока и другое состояние
запущенной игры между версиями не сохраняются. Проверка точных замен не доказывает,
что модель выбрала именно нужные места или написала безошибочный JS —
проверьте результат и управление. Подробности и обновление: `EDIT-UPDATE.md`.

### Защита от «обещания вместо результата»
В обычном чате запросы на браузерную игру, сайт или сцену от первого лица
переводятся в режим HTML-артефакта:
- генераторы картинок/видео, просмотр скриншота страницы и Python не предлагаются
  модели как замена интерактивному HTML; сервер также отклоняет их незапрошенный вызов;
- короткие продолжения вроде «ну че там» сохраняют исходную задачу, а явная просьба
  «нарисуй картинку поля» переключает на изображение;
- в режиме создания, если вместо полного HTML пришло обещание или оборванный блок, сервер один раз
  просит завершить код без инструментов и без дополнительного списания сообщения.
  Старый незавершённый текст заменяется новым, чтобы не ломать Markdown;
- после второго неудачного ответа показывается ошибка, а не заявление о готовой игре.
  Уточняющий вопрос/явный отказ не запускает автоматический повтор;
- режим не требует HTML от помощника, работающего с файлами в папке или на ПК.

Это ограниченная языковая эвристика, не гарантия правильного понимания любых формулировок.
Наличие полного HTML тоже не гарантирует качество игры: нужна существующая самопроверка
браузера и проверка управления человеком. См. `CHAT-UPDATE.md`.

Один запрос к текстовой модели ограничен 180 секундами, включая чтение потока.
Настройка: `MODEL_REQUEST_TIMEOUT_MS=180000` (1000–600000 мс).
До появления текста каждые 30 секунд показывается статус ожидания.
Повторное завершение HTML — отдельный запрос с тем же таймаутом.
Провайдер-специфичные настройки reasoning автоматически не меняются.

Диагностика чата: строки `[чат]` в логах и поле `chats` в защищённом
`GET /api/admin/monitor`: время до первого текста/общее время, количество запросов,
вызовов инструментов и автоповторов, исход. Тексты запросов, размышления и API-ключи
в эту диагностику не записываются. Последние 100 записей хранятся только в памяти.

## Файлы и архивы от модели
Попросите, например: «сделай сайт и скинь в папке» или «дай проект архивом». Модель присылает файлы блоками вида ` ```css:moy-sait/style.css `, а Premier показывает карточку с кнопками **Скачать ZIP**, **TAR.GZ** и **Превью** (для сайтов style.css и script.js подключаются автоматически). Каждый файл можно раскрыть, скопировать или скачать отдельно. Архив собирается прямо в браузере. 7z/rar браузер создавать не умеет — вместо них ZIP, он открывается любым архиватором.

## Проекты и инструкции
Шестерёнка у проекта (или «+» у «Проекты») → название и инструкции для модели.
Инструкции автоматически добавляются ко всем чатам проекта.

## Файлы и картинки
Скрепка, перетаскивание в поле ввода или вставка (Ctrl+V).
- Текст и код: txt, md, csv, json, js, py и др.
- Документы: PDF (через pdf.js с CDN), DOCX, XLSX, PPTX — читаются прямо в браузере.
- Картинки: уменьшаются до 1280 px и отправляются модели. В Панели отметьте
  «Модель понимает картинки» у моделей с поддержкой зрения (GPT-4o, Claude, Gemini и т.п.).

## Публикация сайтов
В окне превью — кнопка «Опубликовать». Сайт получает ссылку вида `/s/abc123`,
её можно отправить кому угодно. «Снять» — удаляет публикацию.
Сайты лежат в `data/sites/` и открываются в изолированной песочнице.
Лимит: 20 публикаций в час с одного IP, до 2 МБ. Отключить: `PUBLISH=off`.

## Интернет
Кнопка «Интернет» у поля ввода разрешает модели искать в сети и читать страницы.
Модель сама решает, когда искать; в ответе — шаги («Искал…», «Прочитал…») и источники.
- Поисковик выбирается в Панели → «Интернет»: DuckDuckGo (без ключа, по умолчанию),
  Tavily, Brave Search или Serper (нужен ключ — надёжнее и быстрее), либо «Выключен».
- Лучше всего работает с моделями, поддерживающими function calling (GPT-4o, Claude,
  Gemini, DeepSeek, Qwen и др.). Если модель не умеет инструменты, Premier сам ищет по
  вопросу пользователя и подкладывает результаты.
- Чтение страниц защищено от доступа к внутренним адресам (localhost, локальная сеть).

## Настройки аккаунта
Кнопка с именем внизу слева: имя (вход — через Google), тариф и расход за сегодня, память, смена пароля, «выйти на других устройствах» и удаление аккаунта (по паролю; чаты, память и файлы удаляются навсегда).

## Чаты на сервере
Чаты и проекты каждого аккаунта хранятся на сервере (в базе `data/premier.db`) и одинаковы на всех устройствах. Браузер держит копию для скорости; при открытии вкладки чаты подтягиваются заново. Старые чаты из браузера загружаются на сервер при первом входе.

## Память
Модель сама запоминает важное о пользователе (инструменты `remember`/`forget`) и учитывает это во всех чатах. Посмотреть, добавить, удалить или выключить память: нажмите на своё имя внизу слева → «Мой аккаунт». Хранится в `data/memory/`.

## Выполнение кода (Python)
Модель запускает Python: точные расчёты, анализ данных, графики, файлы Excel/Word/PowerPoint/PDF. Картинки показываются в чате, остальные файлы — кнопками «скачать». Файлы лежат в `data/files/` и доступны только владельцу.

Безопасный режим — Docker-контейнер без интернета (512 МБ памяти, 1 CPU, 60 секунд, до 128 процессов, без прав root, система только для чтения). Код программы подключается только для чтения, а файлы, которые она создаёт, лежат в памяти контейнера (до 50 МБ) и забираются одним архивом после завершения — программа не может забить диск сервера или подложить ссылку на чужой файл. Установка на VPS один раз:
```
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER     # чтобы сервер мог запускать Docker без sudo (перезайдите в SSH)
docker build -t premier-python sandbox
```
Проверка: **/panelp → Инструменты → Python → Проверить**. Без Docker функция просто выключена.
Для своего компьютера можно без Docker: `CODE_RUNNER=local node server.js` (код выполняется без изоляции — не используйте на публичном сервере!).

## Встроенный браузер (Chromium)
Модель получает настоящий браузер:
- **Чтение сайтов полностью** — `fetch_page` открывает страницу в Chromium, поэтому работают сайты, которые подгружают содержимое скриптами.
- **Скриншоты** — модели с галочкой «понимает картинки» получают инструмент `view_page` и могут посмотреть, как выглядит страница.
- **Самопроверка сайтов** — после того как модель сделала сайт, Premier открывает его на «компьютере» (1280px) и «телефоне» (390px), ищет ошибки JavaScript, битые ресурсы и горизонтальную прокрутку. Если что-то не так, модель сама исправляет сайт (в чате видно «Проверил сайт в браузере»). Модели с картинками ещё и смотрят скриншоты.

Установка на VPS (Ubuntu/Debian), один раз в папке проекта:
```
npm install
npx puppeteer browsers install chrome --install-deps
```
Если Chrome не запускается из-за системных библиотек, можно поставить системный Chromium (`sudo apt install chromium` или `chromium-browser`) и запускать так: `CHROMIUM_PATH=/usr/bin/chromium node server.js`.

Проверка и настройки: **/panelp → Инструменты** («Проверить браузер», включить/выключить браузер и самопроверку). Нужно около 300–500 МБ свободной памяти; браузер сам закрывается после 3 минут простоя. Одновременно открывается не больше 2 вкладок (`BROWSER_PAGES`). Внутренние адреса сервера (localhost, 192.168.* и т.п.) браузеру недоступны.
### Защита браузера и совместимость
- Sandbox Chromium **включён по умолчанию**. Не запускайте приложение от root. Если ОС запрещает sandbox, браузер выдаёт ошибку, а не отключает защиту автоматически. Проверьте поддержку user namespaces и политики AppArmor; не ослабляйте ограничения systemd вслепую.
- HTTP/HTTPS браузера идут через локальный авторизованный прокси `browser-proxy.js`. Он проверяет все IP из DNS-ответа и подключается к выбранному числовому IP без повторного разрешения имени. Разрешённые домены не кешируются. Каждый новый запрос HTTP и туннель HTTPS проходят проверку; внутренние и служебные IP запрещены.
- Разрешены только порты **80 и 443**. Сайты на нестандартных портах, `file://`, FTP и незашифрованный WebSocket `ws://` не поддерживаются. HTTPS и `wss://` используют проверяемый CONNECT. Обход прокси для loopback, QUIC и прямой UDP WebRTC отключены; service workers в рабочих страницах отключены.
- `BROWSER_NO_SANDBOX=1` — явный небезопасный режим с предупреждением в логах. Используйте только при отдельной изоляции браузера; сам по себе сетевой прокси не заменяет OS sandbox.
- Встроенная защита не заменяет отдельного ограничения исходящей сети на уровне ОС/контейнера и обновлений Chromium. Перед публичным запуском проверьте браузер на целевом сервере.
- При SIGTERM/SIGINT приложение закрывает Chromium и прокси (до 5 секунд на завершение).

Дополнительная проверка настоящего Chromium без внешнего интернета:
```
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```
Нужен установленный Puppeteer или Playwright. Smoke-тест использует только локальный тестовый сервер; публичный адрес подменяется локальным соединением исключительно внутри теста, не в приложении.

Без установки всё работает как раньше — просто без браузера.

## Безопасность
- Ключи хранятся только на сервере (в базе `data/premier.db`) и не уходят в браузер.
- Пароль панели проверяется на сервере. Смените его перед публикацией:
  `ADMIN_PASSWORD=ваш_пароль node server.js`
- Не публикуйте папку `data/` в открытый репозиторий.
- **Длина ответа.** У каждого тарифа есть «Макс. длина ответа, токенов» (по умолчанию Free 8000, Pro 16000, Max 32000; пустое поле — без ограничения). Если ответ упёрся в предел, пользователь видит подсказку написать «продолжи».
- **Пробный Pro** выдаётся не чаще одного раза в 30 дней с одного IP — остальные новые аккаунты с этого адреса получают Free.
- **IP за прокси.** Ограничения попыток входа, регистраций и публикаций считаются по IP. Если Premier стоит за nginx/Caddy на этой же машине или в Docker, IP берётся из `X-Real-IP` / `X-Forwarded-For` автоматически. Прокси на другом сервере — `TRUST_PROXY=1`; без прокси — можно `TRUST_PROXY=0`. В nginx добавьте `proxy_set_header X-Real-IP $remote_addr;`.
- **Вход в панель:** после 5 неверных паролей с одного IP — пауза 10 минут, и не больше 50 ошибок в час со всех адресов.
- **Размер запросов:** обычные запросы до 1 МБ, чаты — до 15 МБ, публикация — до 3 МБ, сообщение с картинками — до 40 МБ.
- **Чтение сайтов моделью** не пускает во внутреннюю сеть: локальные и частные адреса, облачные метаданные (169.254.169.254) и их обходные записи (`[::ffff:7f00:1]`, `127.1`, `0x7f000001`, NAT64/6to4) блокируются, а адрес проверяется ещё раз в момент соединения — сайт не может подменить IP после проверки (DNS rebinding).
- **Помощник на компьютере** в авто-режиме снова спрашивает подтверждение, если в этом ответе модель читала сайты (текст на странице мог подсунуть ей чужую команду).
- **Ошибки в коде** пользователь видит как «Внутренняя ошибка сервера», а подробности уходят в журнал (`/panelp → Обзор`) и в оповещения — см. «Мониторинг».

## Настройки
- `PORT` — порт (по умолчанию 3000)
- `HOST` — адрес, на котором слушать (`127.0.0.1` — только через прокси; по умолчанию все адреса)
- `ADMIN_PASSWORD` — пароль панели, от 12 символов (простой или пустой не принимается — будет создан случайный, см. выше)
- `PUBLISH=off` — выключить публикацию сайтов
- `TRUST_PROXY` — `1` всегда верить заголовкам прокси, `0` никогда (по умолчанию — только от локального прокси)
- `PUBLIC_URL` — адрес сайта для возврата после оплаты (например, https://premier.ru)
- `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET` — ключи Platega (можно ввести в Панели)

Чаты и проекты пока хранятся в браузере пользователя.

## Доступ к компьютеру (Premier Agent)
Кнопка «Компьютер» в чате. Модель может выполнять команды в терминале, создавать папки и файлы в любом месте
(например, на рабочем столе), править код, запускать сайты, игры и программы. Работает на Windows, macOS и Linux.

Подключение (один раз): «Компьютер» → получить код →
- **Windows:** скачать `Premier-Agent.cmd` и запустить двойным щелчком (код уже внутри; `.cmd` запускает `premier-agent.ps1`, который сам проверит Node.js 18+ и при отсутствии установит — winget или тихий MSI с nodejs.org);
- **macOS/Linux:** выполнить в Терминале показанную команду (`curl … premier-agent.js && node premier-agent.js КОД`).

Помощник (`desktop/premier-agent.js`, без зависимостей) привязывается к аккаунту и ждёт задач с сервера, пока его окно открыто.
- Команды, запись, правка, перемещение, удаление и открытие файлов выполняются **только после «Разрешить»** в чате;
  просмотр и чтение — без подтверждения. В меню кнопки можно включить «Выполнять без подтверждения» (опасно).
  Даже в этом режиме Premier снова спросит разрешение, если в этом ответе модель читала сайты: текст на странице мог подсказать ей чужую команду.
- Помощник блокирует явно разрушительные действия: форматирование, `rm -rf /`, удаление домашней папки, рабочего стола
  и системных папок.
- Остановить доступ: закрыть окно помощника или нажать «Отключить компьютер» в меню (ключ помощника аннулируется).
- Долгие процессы (сервер, игра) модель запускает в фоне; обычная команда ограничена 10 минутами.
- До 25 шагов с инструментами за ответ, каждый шаг списывается как сообщение.
- Ключ помощника хранится в `~/.premier-agent.json`, на сервере — только его хэш (в базе).

## Озвучка ответов
Кнопка с динамиком под ответом читает его вслух **прямо на вашем сервере** — без внешних сервисов, ключей и оплаты.

- **Основные голоса — Вера (женский) и Глеб (мужской)** на [Vosk TTS](https://github.com/alphacep/vosk-tts) (нейросеть, лицензия Apache 2.0). Чистый звук без «шершавости» и самая высокая разборчивость из протестированных свободных голосов (ошибок распознавания ≈10%; RHVoice — 13%, Piper — 16–38%).
- Числа читаются словами («990» → «девятьсот девяносто»), английские слова — по-русски («Deploy» → «деплой»).
- Модель не входит в архив: `./tts/setup.sh` скачивает её (~750 МБ), ставит Python-пакеты в `tts/vosk/venv` и сжимает модель. `deploy/install.sh` делает это сам. После установки перезапустите Premier.
- Нагрузка: ~650 МБ памяти (модель держится загруженной), после запуска сервера модель грузится 20–80 с, фраза синтезируется примерно в 1,5 раза быстрее, чем звучит (2 ядра). Готовый звук кэшируется.
- **Запасной движок — RHVoice** (уже в комплекте, `tts/rhvoice`, ~30 МБ, голоса Елена и Александр): включается сам, если Vosk не установлен. На слабом сервере (меньше 1,5 ГБ памяти) ставьте только его: `./tts/setup.sh --no-vosk`.
- Голос и скорость (0,85–1,5×) пользователь выбирает в «Настройки аккаунта → Голос». Скорость меняет сам синтезатор, поэтому речь не «плывёт».
- Лицензии (коммерческое использование разрешено): Vosk TTS и модель — Apache 2.0; RHVoice — `tts/rhvoice/LICENSES.md`.
- Если синтезатор недоступен, ответы читает голос браузера, как раньше.
